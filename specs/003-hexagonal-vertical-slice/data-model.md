# Data Model: Hexagonal Architecture & Vertical Slice Migration

**Feature**: `003-hexagonal-vertical-slice`
**Date**: 2026-08-22

This migration introduces **no new database tables or columns**. The data model
documents (1) the existing persisted entities whose ownership moves with the
refactor and (2) the new code-level entities created by the hexagonal vertical
slice structure.

## Persisted Entities (unchanged by the migration)

### User

- **What it represents**: an authenticated platform user (RBAC profile:
  `syndic` / `owner` / `tenant`).
- **Ownership after migration**: domain logic owned by the `auth` feature;
  persistence adapter at `internal/auth/postgres_repository.go`; shared type at
  `internal/shared/model`.
- **Fields**:

  | Field | Type | Notes |
  |-------|------|-------|
  | id | int64 | generated by Postgres |
  | email | string | unique, stored lowercased |
  | name | string | required, max 200 runes |
  | role | string | one of `syndic`, `owner`, `tenant` |
  | password_hash | string | Argon2id PHC string (peppered) |
  | created_at | timestamp | generated by Postgres |
  | updated_at | timestamp | generated by Postgres |

- **Validation rules** (kept in `auth/domain.go` / `service.go`):
  - name required, max 200 characters
  - email must be a valid bare address (no display-name form)
  - password 8–1024 bytes
  - self-selected role must be `owner` or `tenant`; `syndic` granted out of band
- **State transitions**: none today. Future role transitions belong to the
  `Election` feature (`002-election-module`), not this refactor.
- **Table**: `users` (`migrations/0001_create_users.up.sql`).

### Session

- **What it represents**: a server-side HTTP session. The browser holds a random
  opaque token; Postgres stores its SHA-256 hash, the optional `user_id`, a CSRF
  token, and an expiry.
- **Ownership after migration**: shared infrastructure at
  `internal/shared/session`; consumed by `shared/httputil` middleware and the
  `auth` handler.
- **Fields**:

  | Field | Type | Notes |
  |-------|------|-------|
  | token_hash | string | hex SHA-256 of the browser token |
  | user_id | int64/null | null = anonymous session |
  | csrf | string | random token bound to the session |
  | expires_at | timestamp | `SESSION_TTL` from config |

- **Lifecycle / state transitions**:
  1. `Create` — anonymous session inserted (user_id null).
  2. `Get` — lookup by token hash; expired rows are deleted and treated as not
     found.
  3. `BindUser` — token rotated (fixation prevention) and `user_id` attached.
  4. `Delete` — logout removes the row.
- **Validation rules**: token is 32 cryptographically random bytes, base64url;
  stored only as SHA-256; CSRF must match on every state-changing form.
- **Table**: `sessions` (`migrations/0002_create_sessions.up.sql`).

## Code-Level Entities (introduced by the migration)

### Feature Slice

- **What it represents**: a self-contained vertical package under
  `internal/<feature>` that owns everything about one user-facing feature.
- **Structure**: `domain.go`, `ports.go`, `service.go`, `http_handler.go`,
  `module.go`; `postgres_repository.go` when the feature persists data.
- **Relationships**: depends only on `internal/shared/*` and its own
  subpackages. Must not import another feature slice.
- **Instances after migration**: `auth` (persists users), `home` (no
  persistence today).

### Port

- **What it represents**: an interface owned by a feature (or shared package)
  that decouples business logic from infrastructure.
- **Attributes**: owner package, method set, implementers.
- **Validation**: methods are context-aware and return domain errors; ports
  never reference HTTP or SQL types.
- **Relationships**: implemented structurally by adapters; wired at the
  composition root.

### Adapter

- **What it represents**: an implementation of a port for a specific transport
  or persistence technology.
- **Kinds**: `http_handler.go` (inbound, HTTP) and `postgres_repository.go`
  (outbound, SQL).
- **Validation**:
  - handlers: parse/validate request → exactly one service call → render or
    redirect; no business rules and no SQL
  - repositories: the only files in a feature that execute SQL
- **Relationships**: implements one or more ports of its own feature; may
  structurally satisfy ports owned by other features/shared packages when wired
  by `internal/app`.

### Domain Service

- **What it represents**: the business-logic unit of a feature slice.
- **Attributes**: method set exposed to handlers; ports it depends on.
- **Validation**: imports only domain types, ports and allowed shared packages;
  never `net/http` or `database/sql`.
- **Relationships**: called by `http_handler.go`; calls ports.

### Shared Infrastructure

- **What it represents**: cross-feature capabilities under `internal/shared/`.
- **Instances**: `config`, `database`, `httputil`, `model`, `password`,
  `session`, `templates`.
- **Validation**: a shared package must not import any feature package; it may
  import other shared packages.
- **Relationships**: features may import shared packages; the composition root
  wires concrete shared adapters into features.

## Dependency Map (target)

```text
internal/app
  ├── internal/auth
  ├── internal/home
  └── internal/shared/*
        ├── internal/shared/session
        ├── internal/shared/database
        ├── internal/shared/httputil
        ├── internal/shared/model
        ├── internal/shared/config
        ├── internal/shared/password
        └── internal/shared/templates

internal/auth  → internal/shared/{session,httputil,model,password,templates}
internal/home  → internal/shared/{session,httputil,model,templates}
internal/shared/* → never imports internal/auth or internal/home
```
